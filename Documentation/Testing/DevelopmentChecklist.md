# Development checklist and test plan

**Status:** Stage 1 in progress. The documentation and local repository are not a runtime validation. Items below refer to this project's code and environment, not to a vendor's claims. Record the date, version, result and sanitized evidence with each completed check.

## Stage 1 — exit checklist

- [x] Preserve the master requirements; document architecture, security boundaries and the desired risk settings without changing them.
- [x] Review official Exness demo, execution, margin, symbol, timing and legal materials, and MetaQuotes account/calendar/terminal behavior.
- [x] Prepare Windows steps, a versioned project starter and a blank inventory for the exact eight instruments.
- [ ] **First task:** connect Windows MT5 to a Standard demo, leave Algo Trading off, and open MetaEditor. No orders or deposits. Record MT5 build in the follow-up.
- [ ] Inspect the eight account-specific specifications and note unavailable/missing fields. Verify server offset, session availability and the Calendar tab with observed timestamps, rather than copying advertised values. Record midnight reset evidence separately from commercial swap rollover.
- [ ] Identify the applicable broker entity and verify the terms for automated collection and later demo order tests. Confirm pass/fail or explicit unavailability per workflow. Obtain broker clarification for ambiguous use. No collector or trading EA runs against Exness before the applicable gate.
- [ ] Confirm retail hedging mode and opposite-position permission via authoritative account evidence or a permitted, read-only MT5 diagnostic. Do not place an offsetting test order just to check Stage 1 account mode. Calendar programmatic freshness and tick throughput get further validation when the probe is permitted.
- [ ] Clone the project on Windows and verify local Git history. The private remote may be attached from the user's GitHub account; never make it public to solve a Git setup problem.

Treat a missing supported symbol or unverified account capability as a blocker for the affected path. If broker permission blocks a native probe, continue **offline only** by explicit exception; do not mark on-broker feasibility passed. Stage 1 requires evidence, not a real-money trade. If no quotes arrive outside market hours, don't infer instrument availability or calendar health from that interval.

### Required risk and recovery cases for later stages

- At $10 equity, check below/equal/above the modeled $1 single-entry risk, $4 aggregate risk and $7 projected margin boundaries. The model must round volume down or reject; an unsafe minimum lot must never be rounded up. Test non-USD deposit currencies and adding risk while a previous symbol still has positions.
- Day start $100, later peak $150: compare equity immediately above $90 to $90 and below. Test floating P/L, costs, missed or mid-day startup snapshots, restart around midnight, clock skew, day transitions with no ticks, preservation of latches, and no early drawdown reset. Separately test $10 start and $160 target equality; new entries remain off after the target even if equity falls while positions are managed. Verify explicitly authorised restart and policy precedence. Test capital movements per the policy agreed before Stage 5; never silently count a deposit as strategy profit.
- Check positions without SL (manual and unexpected broker outcomes), size-step partial close, minimum residual size, buy/sell trailing monotonicity and freeze constraints. Check closing/unwinding either hedge leg under HMR, lost acknowledgements, outstanding orders when pausing/switching and side effects when the broker is unreachable. A disconnected tester cannot claim a close or amendment it has not confirmed.
- Verify no new real-account entry on install or restart, no trades on unapproved account modes, safe behavior when settings are malformed, no cap override via intensity, and independent management if the API, UI, Telegram, calendar, disk or network is impaired. Test backup/restore of daily state and detection of missing audit data.

## Exness demo benchmark protocol

1. **Observation first.** Establish server/account type, MT5 build, currency, leverage, actual symbol capabilities, and clock/calendar provenance. Record access that is not available. With authorised collection, measure age and coverage of quotes, Bid/Ask spread in points and account-currency terms, and gaps per instrument across comparable sessions. Windows terminal, no orders, then offline spread/cost replay.
2. **Comparable forward runs.** Only on demo and after broker and safety approval, run the same locked EA/config, account currency, comparable leverage, virtual equity/risk budgets and observation windows across available accounts. Version the setup, record execution modes (including Pro mode if selectable), and match observations or stratify by symbol, session, volatility, news and side. Each instance still allows only one selected entry instrument; rotate instruments and retain all-account exposure checks. Allow “no legal size” as a valid result at $10-equivalent equity. Separately run explicit safety fixtures on demo when appropriate, including opposite tickets, broker-confirmed stop, partial close, cancel/replace and restart. Keep fixture metrics apart from strategy results.
3. **Measure orders as well as profits.** For each request record its intended pricing benchmark, client request time, response/retcode, fills and their times/prices/volumes, deposit-currency fees, margin before/after and stop confirmation. Report rates with denominators for fill, rejection, partial fill and requote, plus median and tail latencies/spreads/slippage. Use a monotonic client clock for request timing; do not claim pure server processing time. Tie slippage to side-correct entry, exit and partial-close reference prices. Derive realized P/L from broker deals and fee ledger to avoid double-counting costs embedded in fill prices or booked at open.
4. **Compare evidence, not advertised spreads.** Use net expectancy (average net result per strategy trade), drawdown, sample counts and uncertainty by instrument, strategy, regime and session. Treat related trades as clustered so sample counts don't imply independent evidence. Predefine evaluable coverage and uncertainty standards before looking at final results. Stress test spread, commissions, fill probability, latency and adverse slippage with replay and clearly separate estimates/shadow from actual demo broker executions.
5. **Report and decide.** Retain a reproducible, sanitized benchmark summary. Determine whether any suitable account qualifies only from consistently usable fills, affordable minimum size and validated net performance. A lack of sufficient data or a failure of any safety test means “not ready,” and demo does not demonstrate that real accounts would fill identically. Do not add real capital to make a test pass.
